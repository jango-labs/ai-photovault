# Contributing

Thanks for helping. Please read [SECURITY.md](SECURITY.md) first and report vulnerabilities privately.

## Ground rules

- **Privacy first.** No telemetry, no network calls with user photos or metadata to third parties by default, originals are never modified.
- **Never commit** photographs, `.env`, backups, tokens or personal data. `npm run scan:secrets` must stay clean (CI enforces it). Sample images must be generated by `scripts/fixtures/generate.mjs` or be CC0/public domain with the licence recorded in your PR.
- Keep changes small and tested. Behaviour changes need a test; schema changes need a new numbered migration in `app/server/migrations` (never edit an applied one).

## Setup

```bash
npm ci
npm run check          # lint, typecheck, unit + web tests, build
```

Database tests (`npm run test:db`) need PostgreSQL 17 with pgvector and a superuser the tests can use. They create and drop throw-away `photovault_*` databases only. Point them at your own scratch server:

```bash
export PGHOST=127.0.0.1 PGPORT=5432 PGUSER=postgres PGPASSWORD=...        # a scratch instance, not data you care about
export PHOTOVAULT_DB_OWNER_PASSWORD=... PHOTOVAULT_DB_APP_PASSWORD=... PHOTOVAULT_DB_SERVICE_PASSWORD=... \
       PHOTOVAULT_DB_DELIVERY_PASSWORD=... PHOTOVAULT_DB_BACKUP_PASSWORD=...  # any throw-away values
npm run test:db
```

CI shows a working setup (`.github/workflows/ci.yml`). `scripts/e2e-native.sh` runs a full clean-install test.

## Style

TypeScript strict, ESLint clean, no `any` without a comment. Plain, honest UI text: say what was measured vs. generated, never invent data.

## Pull requests

Describe what and why, how you tested it, and any privacy or security impact. By contributing you agree your work is released under the [MIT licence](LICENSE).
